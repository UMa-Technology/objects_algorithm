# objects_algorithm

An astronomy-algorithm Flutter FFI plugin built on [AA+](http://www.naughter.com/aa.html): coordinate
transforms; Sun, Moon, planet and comet positions; rise, transit and set times; twilight and the
observing-night window.

Supported platforms: Android / iOS / macOS / Windows. The C++ sources are maintained in one place,
`src/`, and every platform compiles them from source, so callers never need to copy any C++ files.

## Integration

```yaml
dependencies:
  objects_algorithm:
    git:
      url: "https://github.com/UMa-Technology/objects_algorithm.git"
      ref: "v0.2.0"
      path: "flutter/objects_algorithm"
```

For local development, override with a path dependency:

```yaml
dependency_overrides:
  objects_algorithm:
    path: ../objects_algorithm/flutter/objects_algorithm
```

## Usage

```dart
import 'package:objects_algorithm/objects_algorithm.dart';

final night = astroNightForSiteDate(
  timezoneName: 'Europe/Paris',
  nowUtc: DateTime.now().toUtc(),
  obs: Geography(48.8566, 2.3522),
);
```

For the full field reference of solar events and the observing-night window, see
[docs/app_call_guidance.md](../../docs/app_call_guidance.md). For what does and does not belong in
`lib/`, see [docs/scope.md](../../docs/scope.md).

## Layout

```
src/                        C++ sources, the single source of truth for all platforms
  aaplus/                     upstream AA+ algorithm implementation (119 .cpp files incl. AATest.cpp)
  aainterface/                extern "C" bridge layer (33 .cpp files); these are the symbols dart:ffi looks up
  CMakeLists.txt              build definition shared by Android and Windows
android/build.gradle        externalNativeBuild points at ../src/CMakeLists.txt
windows/CMakeLists.txt      add_subdirectory(../src) + objects_algorithm_bundled_libraries
ios|macos/
  objects_algorithm.podspec
  Classes/
    ObjectsAlgorithmPlugin.m  start of the keepalive chain, see below
    generated/                forwarding files, generated by tool/gen_darwin_sources.sh
lib/                        pure-algorithm Dart layer
example/                    minimal app used to verify the build on all four platforms
```

## After changing the C++ sources

After **adding or removing** files under `src/aaplus` or `src/aainterface`, you must re-run:

```sh
./tool/gen_darwin_sources.sh
```

Android and Windows use `file(GLOB)` and do not need this step. iOS/macOS go through CocoaPods and
need the forwarding files.

If you only change file **contents** without adding or removing files, there is no need to re-run it.

## Why the Apple side is so roundabout

`s.source_files` does not accept relative paths outside the pod directory, so `Classes/generated/`
holds a layer of forwarding files that each contain a single `#include "../../../src/..."` line.
This is the approach used by Flutter's official `plugin_ffi` template.

The real trouble is **symbol survival**. The Dart side looks up `KPCAA*` at runtime via
`DynamicLibrary.process()` + `dlsym`, so there are zero references at link time, and the symbols
have to clear two hurdles:

1. **Archive member selection.** CocoaPods builds this pod as a static library, and the linker
   drops any archive member that is not referenced as a whole, so the forwarding units never make
   it into the final binary. This happens **before** dead-stripping, so neither
   `__attribute__((used))` nor `DEAD_CODE_STRIPPING=NO` can rescue them; those only affect `.o`
   files that are already pulled in.

2. **Dead-stripping.** Even once pulled in, the host app's target defaults to
   `DEAD_CODE_STRIPPING=YES` in Release and prunes unreferenced functions again. This is a link
   setting of the **host target**; the plugin's `pod_target_xcconfig` cannot control it (the pod is
   a static library and does no linking at all).

The 296-entry function-address table in `Classes/generated/objects_algorithm_keepalive.cpp` solves
both at once: taking an address is a link-time reference, which both pulls in the archive member
and survives dead-stripping. `ObjectsAlgorithmPlugin.m` is the start of this chain: the pubspec
declares a `pluginClass`, and the `GeneratedPluginRegistrant` that Flutter generates references it.

The function names are not hand-written; `gen_darwin_sources.sh` extracts them from
`src/aainterface/*.h`. Two rules must not be changed:

- **Only take headers that have a matching `.cpp`.** `KPCAAPlanetaryPhenomena.h` has declarations
  but no implementation; putting it in the keepalive table would cause an undefined symbol.
- **Strip comments before extraction.** `CalculateMoon` in `KPCAARiseTransitSet2.h` is a
  commented-out declaration.

The keepalive table gets the symbols into the binary, but on iOS one host setting is still
required:

> **iOS host apps must set `STRIP_STYLE = non-global` (Strip Style: Non-Global Symbols) for the
> Runner target's Release configuration.**

When Xcode archives an app (`flutter build ipa`, Product > Archive), it strips the final binary
using the host target's `STRIP_STYLE`, whose default is `all`. That removes every `KPCAA*` symbol
from the statically linked app binary, so `DynamicLibrary.process()` finds none of them at
runtime. A plain `flutter build ios` does not strip, so it can't reveal the problem. This is the
same setting Flutter's own FFI documentation asks for when a plugin is linked statically on iOS.
`DEAD_CODE_STRIPPING` can stay at its default.

macOS needs no host setting. If the host uses a bare `use_frameworks!`, this pod is built as a
dynamic framework, and in Release `GCC_SYMBOLS_PRIVATE_EXTERN` defaults to YES, which demotes the
symbols to local; the podspec explicitly turns it off. The macOS podspec also exports only
`KPCAA*` and the plugin class and enables dead-stripping inside the framework, which drops the
unused AA+ coefficient tables.

## Verification

```sh
cd example
flutter build apk --release
flutter build ipa --release --no-codesign   # an archive, so Xcode's release stripping is applied
flutter build macos --release
```

The number of exported `KPCAA` symbols in all three outputs should be **296**:

```sh
# Android
nm -D --defined-only <libobjects_algorithm.so extracted from the apk> | awk '$2=="T"{print $3}' | grep -c '^KPCAA'
# iOS (statically linked into the main binary)
nm build/ios/archive/Runner.xcarchive/Products/Applications/Runner.app/Runner | awk '$2=="T"{print $3}' | grep '^_KPCAA' | sort -u | wc -l
# macOS (dynamic framework)
nm -gU <....framework/Versions/A/objects_algorithm> | awk '$2=="T"{print $3}' | grep '^_KPCAA' | sort -u | wc -l
```

If the numbers do not match, symbols have been stripped. Do not release.

## Known pitfalls

- `src/aaplus/AATest.cpp` is the test driver shipped with upstream AA+ and contains `int main()`.
  All four platform builds exclude it (`list(FILTER ... EXCLUDE)` in `src/CMakeLists.txt`,
  `EXCLUDE_RE` in `gen_darwin_sources.sh`).
- `src/aainterface/*.h` originally had no include guards; `#pragma once` has been added to all of
  them. Without it, the keepalive unit would hit redefinitions when it includes several headers at
  once.
